# c85da06 — Phase 6: verify shared account/session across storefronts in a real browser

Continuation of "continue per specs" — picked up the last remaining item in Phase
6, which needed only verification, no new application code.

## What was actually run

No `chromium-cli` in this environment (same gap the earlier storefront-verification
commit `f70f010` hit), so used `playwright-core` directly against the pre-installed
Chromium at `/opt/pw-browsers` again, installed into the scratchpad rather than the
project (this is a one-off verification script, not project tooling).

1. Reset both storefronts' `.env.local` publishable keys and the backend's
   `STORE_CORS`/`AUTH_CORS` — all were stale from a database reset earlier in this
   session's history (`STORE_CORS`/`AUTH_CORS` were also missing `:8001` entirely,
   a leftover from some earlier single-brand test config that would have blocked
   Brand B outright).
2. Started the backend (`medusa develop`), a real Redis, and both storefronts
   against the existing dev Postgres.
3. Read the actual Next.js starter source
   (`src/modules/account/components/{login,register,overview}/index.tsx`) for
   exact `data-testid` selectors rather than guessing at button text — the
   overview page conveniently exposes `data-testid="welcome-message"` and
   `data-testid="customer-email"` with `data-value` attributes carrying the raw
   values, ideal for assertions.
4. Registered a new account on Brand A (`localhost:8000/us/account`), confirmed
   auto-login.
5. Extracted the `_medusa_jwt` auth cookie Playwright's own browser context was
   holding, and used it directly against the Store API to place a real order as
   that same customer (cart → address → shipping method → payment session →
   complete) — this ties the order to a real `customer_id`, not just an email
   match, and is faster than re-driving a full checkout UI flow already verified
   in `f70f010`.
6. In a **separate browser context** (Brand B, `localhost:8001/jp/account` —
   different origin, so no cookies/localStorage carry over; this is a genuine
   second login, not a lingering session), logged in with the same
   email/password and confirmed the same name and email render.
7. Reloaded Brand B's account overview and confirmed the order placed via Brand A
   appears in its `orders-wrapper`, with the amount shown in the order's own
   currency (USD) rather than incorrectly re-priced for the JP storefront it's
   being viewed from.

## Verified
- Screenshots: registration success (`shared-session-a-registered.png`), Brand B
