# 42074cb — Add shared-inventory integration test (TDD case 4), passing end to end

## What changed
- `apps/backend/integration-tests/http/shared-inventory.spec.ts`: a new integration
  test covering TDD case 4 from `docs/tdd/medusa-catalog.tdd.md` — the shared-inventory
  guarantee. Sets up two sales channels, a US region, a stock location linked to both
  channels, and a variant with 5 units of stock at that shared location. Drives a real
  storefront checkout via Brand A's publishable key: create cart → set shipping address
  → add shipping method → create payment collection → create payment session
  (`pp_system_default`, Medusa's built-in no-op provider) → complete cart. Asserts the
  resulting order is created and the inventory item's available quantity
  (`stocked_quantity - reserved_quantity`) is 3.
- `docs/specs/19-milestones.md`: Phase 1 bullet added for this test, and cases 5-9 (not
  yet covered) spelled out explicitly.

## Why assert on inventory_level, not two HTTP calls
The naive way to "prove" shared inventory is to query both brands' `/store/products`
and check they show the same number. This test instead reads the `inventory_level` row
directly: that row has no sales-channel scoping at all, which is the actual mechanism
that makes the pool shared. Querying it once is a stronger, more direct check than
querying it twice through two different lenses that both happen to point at the same
row.
