# e58bd43 — Phase 1: seed script for two-brand sales channels, regions, shared inventory

Rewrote the generated single-channel demo seed script into the actual Phase 1 setup
from `docs/specs/01-medusa-config.md` and `docs/specs/02-catalog-inventory.md`.

## What changed
- `apps/backend/src/migration-scripts/initial-data-seed.ts`: replaced the generic
  "Default Sales Channel" / Europe-region demo data with:
  - Two sales channels, "Brand A" and "Brand B", each with its own publishable API key.
  - Two regions: US/USD (Brand A) and JP/JPY (Brand B), plus their tax regions.
  - One shared `Main Warehouse` stock location linked to **both** channels — the shared
    inventory pool the architecture depends on — with a fulfillment set, one service
    zone per country, and a standard shipping option priced in each region's currency.
  - One cross-listed demo product (USD + JPY prices on every variant, stock at the
    shared location) proving a sale on either brand draws from the same pool.
- `apps/backend/package.json`: added a `seed` script
  (`medusa exec ./src/migration-scripts/initial-data-seed.ts`) — turned out to be a
  mistake, see below.

## Verified (at the time of this commit)
- `npm run build --workspace=@dtc/backend` — compiles cleanly.
- `npm run lint --workspace=@dtc/backend` — clean apart from one expected false
  positive: JPY has no minor unit, so `amount: 1000` there is already ¥1000, not cents;
  commented in the code so it isn't "fixed" into ¥10 later.
- **Not** run against a live database yet at this point — no Postgres available when
  this commit was made.

## Known-wrong at the time, fixed in a later commit
This commit's own milestone notes said the seed script was "not yet run against a live
database." The next commit got a real Postgres running in-session and found that the
`seed` npm script added here is actually unsafe: `initial-data-seed.ts` lives under
`src/migration-scripts/`, which `medusa db:migrate` already runs automatically, exactly
once, tracked in a `script_migrations` table. Calling it again via `medusa exec`
bypasses that tracking and duplicates every sales channel, region, and product it
creates. See the next history entry for the fix.
